# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A ROS 2 (Humble) colcon workspace: a **virtual-only digital twin** of a
Yaskawa Motoman GP12 arm palletizing mixed-shape parcels (box, cylinder,
flat plate) off a moving conveyor in Gazebo. Perception is ArUco-marker
based (one marker per parcel, glued to its top face); the end effector is a
vacuum gripper; a simulated YRC1000 controller layer gates every pick cycle.
There is no real robot/controller/camera connected — see
`docs/architecture/README.md` for the full node graph, state machine,
launch timing diagram, and the explicit swap points for real hardware later.

The workspace root is on a Windows path but the actual build/run environment
is Linux (WSL) — `/opt/ros/humble`, `gcc` at `/usr/bin/gcc`. Run all `ros2`/
`colcon` commands from a WSL or Linux shell, not PowerShell.

## Build / run commands

```bash
# from workspace root (contains src/, build/, install/, log/)
colcon build --symlink-install
source install/setup.bash

# build a single package (much faster while iterating)
colcon build --packages-select warehouse_pick_place --symlink-install

# run the full digital twin
ros2 launch warehouse_bringup bringup.launch.py
ros2 launch warehouse_bringup bringup.launch.py use_rviz:=false
ros2 launch warehouse_bringup bringup.launch.py use_operator_view:=false  # bare planning-scene RViz instead of the camera+TF dashboard
ros2 launch warehouse_bringup bringup.launch.py world:=warehouse_industrial.world

# health/KPI monitoring
ros2 run rqt_robot_monitor rqt_robot_monitor    # reads /diagnostics
ros2 topic echo /pick_place/stats               # PickPlaceStats: throughput, cycle time, failures

# per-package tests (every package now has a BUILD_TESTING/lint block)
colcon test --packages-select warehouse_pick_place
colcon test-result --verbose
```

There are no application-level unit tests beyond the ament boilerplate
(`test_copyright.py`, `test_flake8.py`, `test_pep257.py` in each Python
package) — testing this system means launching it in Gazebo and observing
behavior (RViz, `ros2 topic echo`, terminal logs), not running a test suite.
See `docs/VERIFICATION.md` for the full command-by-command runbook (every
feature, with expected output and what to check if it doesn't match) and
`docs/architecture/README.md`'s verification checklist for the condensed
version — none of it has been runtime-verified in this repo's own dev
environment (no WSL distro installed there — see
`docs/architecture/README.md` for that caveat).

## Package map (`src/`)

- **warehouse_robot_description** (ament_cmake) — GP12 URDF/xacro, meshes,
  vacuum gripper (`vacuum_gripper.xacro`), cameras (`realsense_d435.xacro`,
  instantiated as `top_camera`/`front_camera` in `gp12.xacro` — camera name
  IS the runtime topic namespace), a cosmetic YRC1000 cabinet
  (`yrc1000_cabinet.xacro`, visual-only, no collision), ros2_control config.
- **warehouse_gazebo** (ament_cmake) — Gazebo worlds
  (`warehouse_industrial.world`), the `conveyor_belt` model (driven by its own
  `ConveyorBeltPlugin`, C++ in `src/conveyor_belt_plugin.cpp`, commanding
  `belt_joint` velocity — retune live via `/conveyor/velocity`),
  `config/parcel_catalog.yaml` (single source of truth: marker ID → shape/
  dims/bin, read by both the spawner and perception), `scripts/generate_parcel_marker_assets.py`
  (build-time step, runs automatically from CMakeLists, generates the
  ArUco marker textures parcels wear), and `product_spawner.py` (spawns
  randomized box/cylinder/plate parcels with an ArUco-marked top face onto
  the belt).
- **warehouse_gripper_control** (ament_cmake, C++) — `VacuumGripperPlugin`,
  a Gazebo model plugin giving the vacuum gripper real physics: `/vacuum_gripper/on`
  and `/off` (`std_srvs/Trigger`) physically attach/detach whatever the
  suction cup's contact sensor currently touches; `/vacuum_gripper/state`
  (`std_msgs/Bool`) is the simulated vacuum-switch grip confirmation.
- **warehouse_controller** (ament_python) — `yrc1000_controller.py`, a
  simulated Yaskawa YRC1000 controller: servo on/off, E-stop, alarms, job/
  cycle telemetry on `/yrc1000/status`, with field names/behavior mirroring
  the real MotoROS2 ROS2 driver so it's a like-for-like swap point later.
  Also exposes `/yrc1000/protective_stop` (distinct alarm code 8020 from
  manual E-stop's 8010) and publishes `/diagnostics`.
- **warehouse_moveit_config** — MoveIt2 config generated by Setup Assistant
  (SRDF, kinematics, OMPL/Pilz planning, `ros2_controllers.yaml` — this is
  the file actually loaded by `gazebo_ros2_control` via `gazebo.launch.py`'s
  `controllers_file` xacro mapping). Loaded via
  `MoveItConfigsBuilder('warehouse_robot', package_name='warehouse_moveit_config')`.
- **warehouse_interfaces** — custom messages: `Detection2D` (legacy, still
  used by the real-hardware ArUco path in `warehouse_aruco_detection`),
  `ParcelDetection` (marker_id/shape/bin/dims/pose/yaw — the sim perception↔
  pick-place interface), `YRC1000Status` (simulated controller status),
  `PickPlaceStats` (throughput/KPI reporting).
- **warehouse_perception** (ament_python) — `parcel_perception.py` is the
  ONLY perception node in the current pipeline: ArUco detection + `solvePnP`
  for a real 6-DOF marker pose, transformed to world frame via known, fixed
  camera extrinsics, looked up against `parcel_catalog.yaml`, published on
  `/parcel_detections`. Config: `config/parcel_perception.yaml`. Publishes
  `/diagnostics`.
- **warehouse_pick_place** (ament_python) — `pick_place_logic.py` is the
  state machine (subscribes `/parcel_detections`, routes by the catalog's
  `bin` field — nothing is hardcoded to a specific shape — debounces per
  marker ID, gates every cycle on `/yrc1000/status`, publishes `PickPlaceStats`
  on `/pick_place/stats`, and auto-triggers `/yrc1000/protective_stop` after
  `protective_stop_threshold` consecutive failures instead of retrying
  forever). `pick_place.py` holds `PickPlaceExecutor`: MoveItPy +
  joint-space IK (position-only; see its "Why joint-space IK?" docstring),
  plus an approximate wrist-yaw alignment (`_wrist_j6_for_yaw`, explicitly
  documented as unverified without a simulator) and real vacuum on/off/
  confirm calls against `warehouse_gripper_control`. Both share one node's
  parameter namespace (`config/pick_place_params.yaml`) — see that file's
  comment for why.
- **warehouse_bringup** — top-level `bringup.launch.py` sequencing everything
  via `TimerAction` (see its docstring's timing ladder, and the Mermaid Gantt
  version in `docs/architecture/README.md`), plus `diagnostic_aggregator`
  (`config/diagnostics.yaml`) and RViz (`config/operator.rviz` by default —
  camera feeds + TF + planning scene; toggle with `use_operator_view:=false`
  for the bare `warehouse_moveit_config/config/moveit.rviz` view). Also
  `hold_position.py`, a standalone debug script.
- **warehouse_aruco_detection** (ament_python) — ArUco marker-based detection
  for the *real* GP12 + RealSense D455 (separate from the sim pipeline
  above, deliberately untouched by the digital-twin rebuild); also marker
  generation and extrinsic calibration tools. Note:
  `launch/aruco_sim.launch.py` is dead weight — it's a stray copy of node
  source code, not an actual launch file, and isn't wired into anything.
- **warehouse_simulation_legacy** — superseded launch/world files, kept for
  reference only. Don't build on this; use `warehouse_gazebo` instead.
- **motoman_ros2_support_packages**, **moveit2** — vendored upstream
  dependencies, not project code.

Every package under `src/` (except vendored/generated ones) has its own
`README.md` with a short purpose/interface summary — check there first for
package-specific detail before reading source. This workspace is not (yet)
a git repository, so there's no CI; `colcon test` is fully scaffolded
(every package has a `BUILD_TESTING`/lint block) for whenever one is added.

## Architecture, diagrams, and swap-to-real-hardware notes

See `docs/architecture/README.md` for the full node/topic graph, the pick
cycle state machine, the launch timing Gantt diagram, and a table of exactly
which simulated piece maps to which real-hardware piece later (arm control,
YRC1000, vacuum gripper, camera). That file also documents known unverified
approximations (wrist-yaw alignment, assumed camera topic names) and a
verification checklist to run on an actual ROS2/Gazebo machine.
